# Kardii AI Companion

Kardii 是一个使用 Tauri 2 制作的跨平台透明悬浮桌宠与 AI 聊天伙伴。

## v1.4 Google / Microsoft 只读连接

- Google Workspace 使用系统浏览器 OAuth 2.0、PKCE S256、随机 `state` 与随机本机回调端口，读取最近 Gmail、Google Calendar、Drive 和 Sheets 项目
- Microsoft 365 使用公共客户端授权码流程与 PKCE，读取最近 Outlook、Calendar，以及 OneDrive 根目录和近期一级文件夹中的项目与在线 Excel；SharePoint 读取可单独勾选
- Google 和 Microsoft 的 OAuth 刷新授权只保存在 Windows 凭据管理器或 macOS 钥匙串；短期访问令牌不落盘，二者都不进入 `localStorage`、JSON 备份或 GitHub
- 已同步概览的标题、时间、服务类型和原项目链接会作为工作台数据保存在本机，并随 Kardii 完整备份导出；断开对应云端连接会删除这些本地概览
- 每个云端服务独立返回同步状态；某一项 API 未启用、权限不足或临时失败时，其他已经读取的服务仍可显示
- 云端概览可按平台和邮件、日历、云盘、表格、SharePoint 类型筛选，并使用系统默认浏览器打开原项目
- 只申请读取权限。v1.4 没有发送邮件、修改日历、上传、覆盖或删除云端文件的命令

### 首次配置 OAuth 应用

Kardii 不内置属于开发者个人的 OAuth Client ID。首次连接前，需要在对应服务商后台创建一个桌面/公共客户端：

1. Google Cloud：配置 OAuth 同意屏幕，启用 Gmail、Google Calendar、Google Drive 与 Google Sheets API，创建“桌面应用”OAuth 客户端；把 Client ID 和控制台提供的可选 client secret 填入 Kardii。
2. Microsoft Entra：注册应用，在“身份验证”中添加“移动和桌面应用程序”平台与 `http://localhost` 回调，允许公共客户端流；使用委托权限 `User.Read`、`Mail.Read`、`Calendars.Read`、`Files.Read.All`，需要 SharePoint 时再添加 `Sites.Read.All`。
3. 登录时 Kardii 会打开系统浏览器。授权完成后回到工作台；访问令牌和刷新令牌不会显示在页面或写入备份。

组织租户可能要求管理员批准读取权限。Google 测试模式也需要先把实际登录账号加入测试用户。

## v1.3 邮箱只读连接

- 工作台侧栏「外部连接」支持最多 12 个 IMAP SSL/TLS 邮箱，并可逐个切换、暂停或恢复同步
- 提供企业微信邮箱 / 腾讯企业邮箱、QQ 邮箱、163、Gmail 和自定义 IMAP 配置，服务器地址可人工修改
- 客户端专用密码或授权码只保存在 Windows 凭据管理器或 macOS 钥匙串，不进入本机 JSON 数据、备份或 GitHub
- 使用 IMAP `EXAMINE` 与 `BODY.PEEK[]` 只读同步，不发送、删除、移动、标记已读或修改邮箱内容
- 可选择只同步新邮件、最近 7 天、最近 30 天、自定义起始日或全部邮件；每批最多读取 30 封并按账号 + UID 去重
- 同步会标记源邮箱中已经删除的本地邮件记录，但不会删除其已经归档到项目、关系库、知识库或待办的内容
- 邮件列表支持按主题、发件人、正文预览和附件名搜索，并可筛选未归档、疑似报价、已归档和源邮箱已删除
- 删除系统凭据、暂停同步、清空本地缓存和移除账号是四个独立操作，界面会明确说明各自影响范围
- 邮件正文与最多 15 个附件先进入 Kardii 本地缓存；单个附件最多 40 MB、每封总计最多 80 MB，跳过项目会显示明确告警
- 继续复用 v1.2 的「AI 分析草稿 → 人工编辑 → 确认保存」流程，可关联关系对象和项目
- 保存邮件时可同时建立一条 Kardii 内部跟进待办，日期和是否创建都由用户确认
- 邮件和附件按外部不可信资料处理，正文中的提示或命令不能改变 Kardii 权限
- 对外发送、删除邮件、自动回复和后台定时同步仍保持关闭

## v1.2 工作台、关系库与常驻 Codex

### 工作台与多文件分析

- 项目详情集中显示关联关系、原始资料和 AI 分析成果
- 一次读取最多 10 份 PDF、Word、PPT、Excel、图片或常见文本，并可勾选把当前 Kardii 聊天一起分析
- 导入流程为“读取预览 → 可选 AI 综合分析 → 人工编辑 → 确认保存”，不会在选择文件后直接写入正式资料
- 确认保存后把原件复制进 Kardii 本机 `workbench-files`，原文件移动后仍可从 Kardii 打开
- 综合成果分别保存摘要、关键事实、承诺日期、待确认问题、风险和下一步，可再次修改或删除
- v1.1 以前已经保存的项目、客户、时间线、知识库和聊天记录会自动迁移，不清空旧数据

### 关系库

- 原“客户库”正式改名为“关系库”
- 支持合作伙伴、服务商、海外仓 / 物流、客户 / 买家、分销商、平台 / 渠道、供应商 / 工厂、机构 / 学校和其他关系
- 公司 / 机构与联系人分开保存，同一个关系对象可以记录多位联系人
- 关系对象、联系人、沟通时间线、项目、文件、背调和分析成果可以互相关联

### 单任务授权

- Agent 生成计划后先展示预计使用的权限范围
- 可选择“允许本任务执行”“仍然逐步确认”或取消任务
- 本任务授权只覆盖计划中声明的低风险操作；计划外工具仍会重新确认
- 非只读终端命令始终重新确认，后端危险命令拦截继续生效

### Codex app-server

- Kardii 优先启动一个本机 Codex `app-server`，复用 ChatGPT 登录并流式显示回答
- 同一聊天在 Kardii 运行期间复用不写入 Codex 历史的内存临时 thread；清空聊天、重新回答或切换 AI 时同步释放 / 重建该线程
- Codex 仍运行在独立空目录、只读沙盒、无网页搜索、无 Apps / MCP / 插件 / 技能 / Hooks、无图片工具和无多 Agent 的边界内
- Codex 只负责语言模型回复；文件、浏览器、剪贴板和终端仍由 Kardii Agent 管理
- 本机 Codex 不支持 app-server 或协议启动失败时，自动回退到 v1.1 已验证的 `codex exec --ephemeral`

## v1.1 Codex、技能与自动化

Kardii v1.1 可以调用用户电脑上安装的官方 Codex CLI，并通过 Codex 自己的 ChatGPT 登录使用账户可用的 GPT/Codex 模型。Kardii 不接收 ChatGPT 密码，不读取或复制 Codex 登录凭据，也不会把登录状态写入备份。

### Codex 登录与安全边界

- AI 设置中新增 `Codex · 使用 ChatGPT 登录`，可检查安装、发起官方登录、刷新状态、测试连接和退出登录
- Codex 登录与额度由官方 Codex 管理；Kardii 只检查 `codex login status`，不会读取凭据文件
- 模型调用始终使用独立空目录与只读沙盒；v1.2 常驻聊天使用不持久化的内存临时线程
- 使用独立空项目目录，并显式关闭 Codex 自带网页搜索、图片工具、Apps、MCP、插件、技能、Hooks 与多 Agent
- Agent 需要搜索、读取文件、操作剪贴板、打开网页或运行命令时，仍通过 Kardii 自己的工具与逐次权限确认
- DeepSeek、Gemini 和 Ollama 继续保留，可以随时切换；ChatGPT/Codex 用量受账户方案和当时额度限制

### 可编辑技能

- 在 Agent 任务中心创建、修改、启用、停用和删除技能
- 技能可设置名称、用途、触发词和完整工作流程
- 创建任务时可手动选择技能，也可由目标文字匹配已启用技能
- 任务保存技能快照，后续修改技能不会悄悄改变正在执行或已完成的任务
- 编辑前自动保留上一版本，可一键恢复
- 完成得满意的 Agent 任务可以转成可继续修改的新技能
- 技能不能增加未授权工具，也不能跳过任务范围确认或高风险操作的再次确认

### 本机自动化

- 创建一次、每天或每周执行的 Agent 自动化
- 自动化可绑定技能，并可选择只创建待执行任务或自动开始
- 支持启用、停用、修改、删除和立即试运行
- 到达执行时间后会打开 Agent 任务中心，避免权限确认或用户问题在后台被忽略
- 错过执行时间后，在 Kardii 下次运行时只补建一次，避免重复创建大量任务
- 自动开始的任务仍受步骤上限、十分钟暂停和逐次权限确认约束
- v1.1 自动化只在 Kardii 正在运行时调度；电脑关机或 Kardii 完全退出时不会在后台执行

## v1.0 Agent

Kardii v1.0 在原有桌宠、聊天、长期记忆、知识库和工作台之上加入通用 Agent 中枢。它不预设用户的职业或工作内容，可以处理生活、学习、研究、创作和受控电脑任务。

### Agent 任务中心

- 在聊天框中切换普通聊天与 Agent 模式
- Agent 先理解目标并生成 2–8 步可检查计划，再逐步执行
- 每次工具返回结果后重新判断下一步，而不是一次生成固定答案
- 独立任务中心显示当前动作、计划进度、AI 判断次数、工具调用次数和完整活动记录
- 支持暂停、继续、取消、失败重试和关闭应用后恢复
- 每个任务默认最多执行 12 步，可在 3–20 步之间调整，防止无限循环和意外费用
- 连续执行达到 10 分钟会自动暂停，用户检查后可以继续
- 任务、过程与最终结果保存在本机，并包含在完整备份中

### v1.0 工具与权限

- 自动只读：公开网页搜索、本机知识库检索、已确认长期记忆检索
- 逐次确认：选择并读取文本文件、读取或写入剪贴板、打开网页、运行受限终端命令
- 资料不足时 Agent 会暂停并向用户提出一个明确问题
- 文件、网页摘要、剪贴板和终端输出均按不可信资料处理，不能覆盖 Agent 安全规则
- 删除数据、系统提权、付款、自动发送消息和静默浏览器操作不在 v1.0 Agent 工具范围内

### 通用化调整

- 新用户的工作台不再预置任何行业、客户、市场或平台示例数据
- 工作台实体表单保持空白，不在输入框中显示特定业务示例
- 商务工作台作为可选模块保留，不再决定 Kardii 的整体定位
- 聊天自动写入商务工作台默认关闭，需要时可在工作台侧栏手动开启
- 文件分析与知识库问答改为通用资料分析，不假设文件属于企业或商务场景

- 迁移码和备份均不包含 API Key

### 用户授权的桌面工具

- 读取用户在系统选择器中亲自选中的 UTF-8 文本或代码文件
- 单次读取或写入系统剪贴板文字，不在后台持续监控
- 使用系统默认浏览器打开经过检查的 `http` / `https` 地址
- 在 Windows `cmd` 或 macOS `zsh` 中运行用户输入并再次确认的单行命令
- 每次工具操作都显示具体内容，仅允许一次，不提供永久授权

- 文件、剪贴板与终端结果只在用户发送下一条问题时交给当前选择的 AI
- 本机保存最近 30 条工具执行记录，可随时清空，不加入备份

### 安全与隐私

- DeepSeek 与 Gemini API Key 不写入源码、配置文件、备份或 GitHub
- Windows 使用系统凭据管理器保存 API Key
- macOS 使用系统钥匙串保存 API Key
- 聊天记录仅保存在当前电脑的 WebView 本地存储中
- 使用 DeepSeek 或 Gemini 时，对话内容会发送至当前选择的云端服务；使用 Ollama 时只发送至这台电脑上的本机服务
- 为了避免误连外部服务器，v0.7 的 Ollama 地址只允许 `localhost`、`127.0.0.1` 或 `::1`
- 语音转文字完全在本机执行，原始录音不保存、不上传
- 离线语音模型仅在用户点击下载后从 sherpa-onnx 官方发布地址获取
- Agent 只会自动使用公开搜索、知识库和长期记忆等只读工具；本地读取、写入、打开网页与终端命令必须逐次确认
- 工具返回内容按不可信资料处理，不能覆盖 Kardii 的系统安全规则

## AI 与语音设置

1. 单击 Kardii 打开聊天窗口，再点击右上角齿轮。
2. 选择 DeepSeek、Gemini、Ollama 或 Codex。
3. DeepSeek/Gemini：粘贴对应服务的 API Key，保存后点击“测试连接”。
4. Ollama：先在电脑上安装并运行 Ollama、下载至少一个模型，再点击“刷新模型”和“测试本机连接”。
5. Codex：先安装官方 Codex CLI，再点击“使用 ChatGPT 登录”；在浏览器完成官方登录后返回 Kardii 刷新并测试连接。
6. 连接成功后关闭设置即可聊天；顶部标签会显示当前使用的服务。

第一次使用语音时，在同一设置面板点击“下载离线模型”。下载和加载完成后，聊天输入框旁会出现可用的麦克风按钮。自动朗读保持默认关闭，需要时再在设置中打开。

不要把 API Key、Codex 登录文件或浏览器登录信息提交到仓库、截图公开或发送给其他人。

python tools/build_animations.py
```

只替换思考、说话或开心的 PNG 帧后，可以仅重建这三种动画：

```

## 本地开发

需要 Node.js 20+、Rust stable，以及对应平台的 Tauri 系统依赖。

```bash
npm ci
npm run dev
```

本地打包：

```bash
npm run build
```

## GitHub Actions

- `Build Kardii macOS Universal App` 构建 Intel + Apple Silicon 通用包。
- `Build Kardii Windows App` 构建 Windows x64 安装包。

工作流会在 `main`、`codex/**` 分支和 Pull Request 上运行，也可以在 Actions 页面手动启动。

## 当前限制

- v1.2 的 Codex app-server 需要本机 Codex CLI 支持对应稳定协议；不支持时会回退到一次性 `codex exec`，回退模式不会逐字显示。
- 图片可以作为原件保存和关联，但 v1.2 尚未自动 OCR 或理解图片内容；分析时只使用文件名和人工备注。
- JSON 完整备份会保存文件索引、提取文字和分析成果，不会重复嵌入 `workbench-files` 中的二进制原件；跨电脑迁移原件仍需单独复制。
- ChatGPT 订阅并不等于通用 OpenAI API 额度；Kardii 的 Codex 模式使用 Codex/ChatGPT 账户当时可用的模型和用量限制。
- Ollama 需要用户另行安装；较大的本机模型会占用更多硬盘和内存，速度取决于电脑配置。
- Agent 使用内置受控工具，尚未接入 MCP 自动工具发现或第三方工具市场。
- 同一时间只执行一个 Agent 任务；多 Agent 并行分工尚未加入。
- 自动化依赖本机 Kardii 保持运行，尚未加入服务器执行端或完全退出后的系统级调度。
- 当前语音输入为“录完后识别”，尚未加入持续监听或唤醒词。
- Windows 与 macOS 安装包尚未进行正式代码签名。
- macOS 首次打开时可能需要在“隐私与安全性”中选择“仍要打开”。
